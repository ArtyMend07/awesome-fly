# Contributing to Awesome Fly

Suggest a repository through an issue or add it directly with a pull request. Corrections, updated links, and clearer descriptions are welcome.

## What belongs here

- Projects that use or help people work with Drosophila connectomes: MaleCNS, FlyWire/FAFB, hemibrain, larval connectomes, or nerve-cord datasets.
- Brain simulations, embodied models, games, creative experiments, data tools, tutorials, and original research code.
- Early prototypes with public documentation and a concrete implementation. Mark an announcement-only repository as **release pending**.
- Substantial ports or extensions that explain and credit their upstream project.

There is no minimum star count. Prefer the original repository over mirrors and unchanged forks. Fly.io hosting projects, aviation projects, and unrelated repositories with “fly” in their name are outside this list's scope.

## Adding an entry

1. Check that the project is not already listed and choose the most relevant section.
2. Read the repository's README and relevant documentation. Check that the source or stated release status matches the proposed description.
3. Use a short English description in this format:

   ```markdown
   - [Project](https://github.com/owner/repo) by **owner** - What it does, the dataset it uses, and any material prototype limitation. [Demo](https://example.com/).
   ```

4. State whether it uses a complete retained graph, an extracted circuit, or only anatomical/visual assets when that distinction matters.
5. Keep the claim proportional to the evidence. A simulation, a learned readout, a scripted motor interface, and biological validation are different things. Link to reported results when claiming measured performance.
6. Verify the repository and optional demo links. Mention upstream changes, archival, missing source, or your affiliation where relevant.

Do not copy marketing claims about consciousness, recovered minds, or demonstrated learning without supporting evidence. Do not include secrets, private download links, game ROMs, or dataset files. Respect upstream licenses and attribution.

## Maintenance

Keep entries concise and group them by purpose, not popularity. Update stale status labels when source code or documented results become available. Change the README's overall review date only after reviewing the whole list; a single entry correction does not require a global date change.

By contributing original list text, you agree to make that contribution available under the repository's CC0 1.0 license. Third-party materials keep their own licenses.
